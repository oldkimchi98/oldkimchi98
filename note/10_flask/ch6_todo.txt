Flask  To-Do 목록과 데이터베이스 CRUD

참고 폴더 : C:\ai\lecNote\10_flask\ch6_todo


1절  전체 처리 흐름

브라우저 요청 → Flask 라우트 → Todo 데이터 검사 → repository 함수 → DB 실행 → 템플릿에 결과 전달 → Jinja2가 HTML 생성
이 흐름은 폴더의 모델·DB·화면 코드를 연결한 설명이다.
현재 폴더에는 app.py와 라우트 구현이 없어서 웹 요청을 연결하는 부분은 확인할 수 없다.
로그인·로그아웃도 화면 코드만 있으며 실제 처리 함수는 이 폴더에 없다.


2절  폴더와 파일의 역할

models.py → Todo 데이터의 항목과 자료형을 정의하는 Pydantic 모델
database/connection.py → repository.py가 실제로 사용하는 Oracle 연결
database/connection_oracle.py → 별도로 마련된 Oracle 연결 예제
database/connection_mysql.py → 별도로 마련된 MySQL 연결 예제
database/repository.py → 등록·조회·수정·삭제 SQL을 실행하는 함수 모음
database/todo_oracle.sql → Oracle 테이블·시퀀스 생성과 CRUD 연습
database/todo_mysql.sql → MySQL 테이블 생성과 CRUD 연습
templates/base.html → 공통 HTML 구조
templates/header.html / footer.html → 공통 머리말과 꼬리말
templates/todo/todos.html → 전체 목록·등록 폼·정렬 선택
templates/todo/todo.html → 한 건 상세보기·삭제 요청
templates/todo/update.html → 내용·완료 여부 수정 화면
templates/page_not_found.html → 서버가 전달한 오류 설명 표시
static/img/todo.png → 로고와 브라우저 탭 아이콘
.env → DB 접속 환경변수 보관. 실제 계정·비밀번호는 메모에 옮기지 않는다.
requirements.txt → 필요한 패키지 이름과 고정 버전 목록


3절  Todo 모델과 데이터 변환

BaseModel → 입력 데이터를 정해진 자료형에 맞춰 검사·변환하는 Pydantic 기본 클래스
id: int | None = None → 정수 또는 None이며 기본값은 None
content: str → 필수 문자열. 생성할 때 반드시 전달한다.
is_done: bool | None = False → 완료 여부. 기본값 False이며 None도 허용
Todo(content="테스트") → 할 일 객체 생성
todo.model_dump() → 모델을 일반 딕셔너리로 변환
Todo(**todo_dict) → 딕셔너리의 키·값을 이름 있는 인수로 풀어 모델 생성
현재 모델에는 내용의 최소·최대 길이 검증이 없다. DB의 길이 제한과는 별개다.
Pydantic의 기본 bool 처리는 문자열 'True'·'False' 등을 변환할 수 있다.
일반 Python에서 bool('False')는 True이므로 모델의 변환과 혼동하지 않는다.


4절  환경변수와 DB 연결

load_dotenv() → .env 값을 환경변수로 읽기
os.getenv('변수명') → 환경변수 값 읽기. 값이 없으면 None
Oracle 변수 → ORACLE_IP, ORACLE_PORT, ORACLE_USER, ORACLE_PASSWORD
MySQL 변수 → DBSERVER_IP, MYSQL_PORT, MYSQL_USER, MYSQL_PASSWORD, MYSQL_DB
cx_Oracle.connect() → Oracle 연결 객체 생성
pymysql.connect() → MySQL 연결 객체 생성
int(os.getenv('MYSQL_PORT')) → 문자열 포트를 정수로 변환
charset='utf8mb4' → MySQL 연결 문자 집합 설정
repository.py는 database.connection의 conn을 가져오므로 현재 사용 DB는 Oracle이다.
connection.py를 import하면 바로 DB 연결을 시도한다. 환경변수와 DB 서버가 준비되어야 한다.
현재 requirements.txt에는 MySQL 연결 코드가 사용하는 pymysql이 없다.
MySQL로 전환하려면 드라이버 설치와 함께 SQL 문법·바인드 표기도 바꿔야 한다.


5절  SQL 실행과 결과 변환

conn.cursor() → SQL 실행과 조회 결과를 다룰 커서 생성
cursor.execute(sql, 값) → SQL과 값을 분리해 실행
Oracle의 :id, :content → 실행할 때 값을 전달할 바인드 변수
fetchall() → 조회된 모든 행 가져오기
fetchone() → 한 행 가져오기. 없으면 None
cursor.description → SELECT 결과의 열 이름 등 메타데이터
desc[0].lower() → 열 이름을 소문자로 변환
dict(zip(keys, row)) → 열 이름과 행 값을 짝지어 딕셔너리 생성
cursor.rowcount → INSERT·UPDATE·DELETE로 영향을 받은 행 수
conn.commit() → 변경 사항 확정
cursor.close() → 커서 자원 정리. DB 연결 자체를 닫는 것은 아니다.
타입 힌트 → 매개변수·반환값의 의도를 표시하며 그 자체가 실행 중 검사를 강제하지는 않는다.


6절  repository.py의 CRUD 함수

get_todos(order='asc') → 전체 목록을 조회해 딕셔너리 목록 반환
order가 'asc'이면 ID 오름차순, 그 외에는 내림차순 SQL을 선택한다.
get_next_id() → NVL(MAX(ID), 0)+1로 표시용 다음 번호 계산
NVL(..., 0) → 테이블이 비어 MAX(ID)가 NULL이면 0으로 대체
fetchone()의 결과는 (4,)처럼 튜플이므로 result[0]으로 숫자를 꺼낸다.
get_todo(id) → 해당 ID의 행을 딕셔너리로 반환. 없으면 None
create_todo(todo) → CONTENT를 등록하고 영향받은 행 수 반환. 보통 성공 시 1
실제 ID는 TODO_SQ.NEXTVAL로 생성한다. 전달받은 todo.id는 INSERT에 사용하지 않는다.
기존 create_todo 설명에는 ID 반환이라고 적혀 있지만 실제 반환값은 행 수다.
update_todo(todo) → ID에 맞는 CONTENT·IS_DONE 수정 후 결과 메시지 반환
delete_todo(id) → ID에 맞는 행 삭제 후 결과 메시지 반환
get_todo의 -> dict 표기와 달리 실제로는 None도 반환할 수 있다.


7절  Oracle과 MySQL SQL의 차이

공통 항목 → ID(기본키), CONTENT(필수 내용), IS_DONE(기본값 0)
IS_DONE=0 → 미완료 / IS_DONE=1 → 완료
Oracle → NUMBER, VARCHAR2, TODO_SQ 시퀀스로 번호 생성
TODO_SQ.NEXTVAL → 다음 시퀀스 번호. 삭제·롤백 등으로 번호에 빈자리가 생길 수 있다.
NOCACHE → 시퀀스 번호를 미리 캐시하지 않음
NOCYCLE → 최댓값에 도달해도 처음부터 반복하지 않음
MAXVALUE 9999 → 시퀀스 번호 상한
MySQL → int, VARCHAR, auto_increment로 번호 자동 생성
MAX(ID)+1은 표시용 계산값이며 실제 다음 시퀀스·자동 증가 번호를 보장하지 않는다.
MySQL 예제의 MAX(ID)+1은 빈 테이블에서 NULL이다. IFNULL(MAX(ID), 0)+1 등으로 보완할 수 있다.
COMMIT → 변경 확정 / ROLLBACK → 아직 확정하지 않은 변경 취소
SQL 파일에는 기존 테이블 삭제·데이터 변경문이 있다. 이번 작업에서는 실행하지 않았다.


8절  공통 화면과 외부 파일

{% extends "base.html" %} → 공통 HTML 틀 상속
{% block content %} → 페이지별 내용을 넣는 영역
{% include "header.html" %} → 공통 파일을 해당 위치에 포함
{{ 값 }} → 값을 화면에 출력
{% if ... %}, {% for ... %} → 조건과 반복 처리
{# 설명 #} → Jinja2 주석. 서버에서 제거되어 브라우저에 전달되지 않는다.
<!-- 설명 --> → HTML 주석. 화면에는 안 보이지만 페이지 소스에는 남는다.
url_for('static', filename='img/todo.png') → 정적 이미지 URL 생성
rel='icon' → 브라우저 탭 아이콘 / rel='stylesheet' → CSS 불러오기
base.html은 Bootstrap 5.2.3 CSS와 bundle JavaScript를 CDN에서 불러온다.
container, btn, table, d-flex 등 → Bootstrap의 디자인·배치 클래스
footer.html은 현재 완전한 HTML 문서 구조다. include용 파일은 footer 요소와 스타일 중심의 조각 형태가 적절하다.


9절  목록·등록·정렬

todos → 서버가 전달해야 하는 목록
next_id → 등록 폼에 표시할 예상 다음 번호
order → 현재 정렬 방향
{% for todo in todos %} → 각 할 일을 표의 한 행씩 표시
todo.id / todo['id'] → 이 예제의 딕셔너리 값을 Jinja2에서 읽는 두 표현
<del> → 완료 내용에 취소선 / <b> → 미완료 내용에 굵은 글씨
<form action='/create' method='post'> → 등록 내용을 POST로 전송
name='content' → 서버가 폼 값을 읽을 때 사용하는 항목 이름
type='hidden' → 보이지 않는 폼 값. 현재 Oracle INSERT는 제출한 ID를 사용하지 않는다.
required → 일반 폼 제출 시 브라우저의 필수 입력 검사
행의 onclick → /todos/ID 상세 주소로 이동
정렬 폼의 method='get' → order를 쿼리 문자열로 전달
onchange='this.form.submit()' → 정렬 선택 변경 시 폼 제출
selected → 현재 정렬 선택값 유지


10절  상세·수정·삭제

todo.html → ID·내용·완료 여부와 목록·수정·삭제 버튼
todo.id ~ '번 상세보기' → Jinja2의 ~로 문자열 연결
update.html → 기존 내용을 value에 넣고 완료 여부에 맞는 option 선택
default('') → 값이 정의되지 않았을 때 기본 문자열 사용. None까지 자동으로 바꾸지는 않는다.
document.getElementById(...).value → 입력 요소의 현재 값 읽기
addEventListener('click', 함수) → 버튼 클릭 동작 연결
fetch(url, {method: 'PUT'}) → 수정 요청
fetch(url, {method: 'DELETE'}) → 삭제 요청
response.ok → HTTP 상태가 200~299인지 확인
response.text() → 응답 본문을 문자열로 읽기
.then(...) → 비동기 결과를 받아 다음 작업 실행
alert(data) → 서버 메시지 표시 / location.href → 다른 화면으로 이동
현재 수정 주소 → /update/ID/내용/완료여부
현재 삭제 주소 → /delete/ID
실제 서버 라우트 구현은 이 폴더에 없다.


11절  세션과 오류 화면

session → 로그인 상태를 확인하는 세션 데이터
session.get('user_id') → 사용자 ID 유무에 따라 헤더 표시
로그인 시 등록·수정·삭제 버튼을 표시하는 조건이 있다.
버튼 표시 조건과 실제 요청의 권한 검사는 별개다. 서버 라우트에서도 검사가 필요하다.
url_for('logout') → logout 이름으로 등록된 라우트의 URL 생성
page_not_found.html → error.description 표시. 오류 핸들러와 상태 코드 설정은 서버에서 해야 한다.


12절  현재 코드에서 기억할 부분

① app.py 부재 → 이 폴더만 보고 flask run이 가능하다고 판단하지 않는다.
② 비로그인 상태에서는 삭제 버튼이 없어 getElementsByClassName('delete')[0]이 undefined일 수 있다.
   요소가 있을 때만 이벤트를 연결하도록 보완할 수 있다.
③ 실패 응답에서 return만 하면 뒤의 .then도 실행되어 undefined 알림·이동이 이어질 수 있다.
   실패 시 throw하거나 성공·실패 흐름을 분리해 보완할 수 있다.
④ 수정 내용이 URL 경로에 그대로 들어간다. 특수문자 처리와 JSON·폼 본문 전송을 고려할 수 있다.
⑤ 수정 입력창의 required는 현재 버튼 클릭 fetch 코드에서 자동 검사되지 않는다.
⑥ repository.py 직접 실행 예제는 실제 INSERT·UPDATE·DELETE를 수행한다.
   실행 형식은 프로젝트 폴더에서 python -m database.repository이며 단순 조회 명령은 아니다.
⑦ get_todo(1)이 None이면 Todo(**todo_dict)에서 오류가 발생한다.
⑧ 이번 주석 작업은 코드 동작을 변경하지 않았으며 실제 DB 연결·SQL 실행도 하지 않았다.


13절  핵심 복습

모델 → 데이터 규칙 / repository → DB 작업 / 템플릿 → 화면 생성
조회 → execute → fetch → 딕셔너리 변환
변경 → execute → rowcount 확인 → commit
브라우저의 완료 값은 문자열, 모델에서는 bool, DB에서는 0·1로 다루는 흐름을 연결해 이해한다.
