3장  Chat Completions API


핵심 이해

Chat Completions → 역할이 있는 messages 목록을 받아 다음 assistant 메시지를 생성한다.
클라이언트 객체가 이전 대화를 자동으로 기억하는 것은 아니다. 필요한 이력을 다음 요청에도 전달한다.
OpenAI SDK의 응답과 LangChain의 AIMessage는 서로 다른 객체다.


전체 흐름

환경 변수 로드 → OpenAI() → messages 구성 → create() → content 추출 → 이력 추가 → 사용량 확인.
예제 모델 → gpt-4.1-nano·gpt-4o-mini·gpt-5-nano. 모델별 지원 옵션을 구분한다.


메시지와 프롬프트

system → 역할·행동 지침. user → 사용자 질문. assistant → 모델 답변.
few-shot → user·assistant 쌍으로 원하는 답변 형태를 보여준다.
대화 이력 → 앞선 질문과 답변을 함께 전달해 이어지는 질문을 이해하게 한다.
사용자가 제공한 사실도 모델의 맥락으로 들어간다. 최신 날씨처럼 실제 조회가 필요한 정보는 외부 도구를 연결한다.


응답과 JSON

response.choices[0].message.content → 일반 답변 문자열.
response_format={'type':'json_object'} → JSON 형식 요청. 프롬프트에도 JSON 출력을 지시한다.
json.loads(content) → JSON 문자열을 Python 객체로 변환.
JSON 형식 성공과 필요한 필드·값의 정확성을 구분한다. 스키마 검증이 필요하면 별도 구조화 출력이나 Pydantic을 사용한다.
Response API 예제도 같은 파일에 섞여 있다. response.output_text는 Responses의 속성이다.
response.output[0] 또는 [1]의 위치를 고정해 답변을 찾으면 출력 항목 종류에 따라 실패할 수 있다.


스트리밍과 설정

stream=True → 완성된 응답 하나 대신 조각을 차례로 받는다.
chunk.choices[0].delta.content → 새로 추가된 텍스트. 값이 있는 조각만 이어 붙인다.
스트리밍 조각은 한 글자나 한 토큰과 항상 일치하지 않는다. 전체 문자열을 누적하려면 parts에 모아 join한다.
부가 사용량 조각 등은 choices가 비어 있을 수 있으므로 확인 후 접근한다.
temperature → 생성의 무작위성. frequency_penalty → 반복 빈도 보정.
reasoning_effort → 추론 모델의 사고 수준. 지원 값과 다른 옵션의 호환 여부는 모델별로 확인한다.


사용량과 오류

prompt_tokens → 입력 토큰. completion_tokens → 출력 토큰. 원문의 반대 주석·누적 변수를 바로잡아 읽는다.
Responses의 대응 필드 → input_tokens·output_tokens.
글자 수와 토큰 수는 다르다. 비용은 해당 모델의 입력·출력·캐시 등 단가에 맞춰 계산한다.
APITimeoutError → 시간 초과. AuthenticationError → 인증. RateLimitError → 요청 제한. BadRequestError → 잘못된 요청.
OpenAIError로 묶어 잡았다고 모두 시간 초과인 것은 아니다. 오류 종류와 응답 상태를 구분한다.


챗봇 구조와 필수 함수

질문 입력 → 종료·빈 문자열 검사 → user 추가 → 요청 → 답변 표시 → assistant 추가.
호출이 실패한 경우 대화 이력과 사용량을 어떻게 처리할지도 정한다.
대화가 길어지면 입력 토큰이 커지므로 최근 이력 유지·요약 등으로 관리한다.
OpenAI(), chat.completions.create(), json.loads(), list.append() → 호출·응답 처리·이력 관리.
