9장 03  Upstage SDK와 LangChain 호출 비교


핵심 이해

OpenAI SDK는 OpenAI 호환 API 형식의 다른 제공자에도 연결할 수 있다.
OpenAI()라는 클래스 이름보다 base_url·키·model이 실제 요청 대상을 결정한다.


SDK 흐름

load_dotenv() → UPSTAGE_API_KEY 읽기 → OpenAI(base_url='https://api.upstage.ai/v1',api_key=...) → chat.completions.create().
원문 채팅 모델 → solar-pro4. 실제 지원 여부는 제공자의 현재 모델 목록으로 확인한다.
messages와 temperature를 전달하고 choices[0].message.content로 답변을 읽는다.
response.usage → 제공자가 반환한 사용량. OpenAI 모델의 가격을 적용하지 않는다.


LangChain 흐름

langchain_upstage의 ChatUpstage → SystemMessage·HumanMessage 구성 → invoke() → AIMessage.content.
UPSTAGE_API_KEY 환경 변수를 사용한다. 다른 제공자의 키와 혼동하지 않는다.
원문의 ChatUpstage에는 명시적인 model 설정이 없다. SDK의 solar-pro4와 같은 모델이라고 단정할 수 없다.
비교하려면 두 방식에 같은 지원 모델을 지정하고 역할·생성 설정도 맞춘다.


점검

채팅 모델 solar 계열과 임베딩 모델 query·passage 계열을 구분한다.
OpenAI 호환 API라는 이유로 모든 OpenAI 내장 도구·Responses 기능이 동일하게 지원되는 것은 아니다.
인증 오류 → 제공자별 키와 endpoint 확인. 모델 오류 → 모델명과 지원 API 확인.
원문 질문은 단일 상식 질문이므로 이를 전체 품질 검증 결과로 확대하지 않는다.


필수 함수

os.getenv(), OpenAI(), ChatUpstage(), SystemMessage(), HumanMessage(), invoke().
base_url → 서버 주소. api_key → 해당 서버의 인증 값. model → 해당 서버에서 지원하는 모델.
