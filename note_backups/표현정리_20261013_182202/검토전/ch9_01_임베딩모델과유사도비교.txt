9장 01  임베딩 모델과 유사도 비교


핵심 이해

Embedding → 문장·문서를 의미를 표현하는 실수 벡터로 변환.
유사도 검색 → 질문 벡터와 가까운 문서 벡터를 찾아 관련 원문을 가져오는 방식.
임베딩 모델은 벡터를 만들고 생성 모델은 답변을 만든다. 역할이 다르다.


전체 흐름

문장 준비 → embeddings.create() → response.data[0].embedding → NumPy 배열 → 차원·유사도 비교.
왕·여왕·노예 문장과 한국어 대응 문장을 비교하며 의미 관계와 다국어 표현을 살펴본다.


거리와 유사도

유클리드 거리 → 두 벡터의 차이를 거리로 계산. 작을수록 가깝다.
내적(dot product) → 대응 성분을 곱해 합산. 크기와 방향의 영향을 함께 받는다.
코사인 유사도 → 내적을 두 벡터의 길이 곱으로 나눈 값. 방향의 유사성을 비교한다.
cosine = np.dot(v1,v2) / (np.linalg.norm(v1)*np.linalg.norm(v2))
영벡터이면 분모가 0이므로 별도로 처리한다. 예제 함수는 이때 0을 반환한다.
일반적인 코사인 유사도는 -1~1이며 큰 값이 더 유사하다. 값 하나를 문장 의미가 같다는 확률로 읽지 않는다.
np.array([3,4])와 [3,4.1] 비교는 계산 원리를 보여주는 예시다.


모델 선택과 차원

text-embedding-3-small → 기본 1536차원. text-embedding-3-large → 기본 3072차원.
dimensions 옵션을 쓰면 지원 모델의 출력 차원을 줄일 수 있다.
Upstage → 별도 키와 base_url 사용. 원문에는 embedding-query, 설명에는 solar-embedding-2-query가 등장한다.
서로 다른 모델의 벡터는 같은 차원이어도 좌표 공간이 다를 수 있다. 모델 A의 문서와 모델 B의 질문을 직접 비교하지 않는다.
검색용 모델이 query·passage를 나누면 질문에는 query, 문서에는 passage 모델을 사용한다.
모델을 바꾸면 문서 임베딩도 그 검색 체계에 맞게 다시 만든다.


비교 해석

같은 제공자의 왕·여왕 문장 → 의미가 가까운 예시. 왕·노예 문장 → 다른 관계를 비교.
영어 왕 문장·한국어 왕 문장 → 다국어 의미 표현을 확인.
몇 문장의 점수만으로 한국어 전체 성능이나 제공자 우열을 확정하지 않는다.
실제 문서와 정답 근거를 준비해 상위 검색 결과가 필요한 청크를 포함하는지, 비용·시간은 어떤지 함께 비교한다.


필수 함수

embeddings.create(), np.array(), np.dot(), np.linalg.norm() → 임베딩·벡터·유사도 계산.
response.data[0].embedding, response.usage → 벡터와 사용량 확인.
